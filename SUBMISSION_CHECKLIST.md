# Final submission checklist

The source is organized for review. Publication, assessor access and personal
reflection are separate actions and are not claimed as completed here.

- [ ] Fill the personal report's author name and student ID.
- [ ] Reproduce and explain the principal methods and reported limitations personally.
- [ ] Record the checks and decisions actually performed by the student.
- [ ] Confirm code-license and course-data sharing choices before public distribution.
- [x] Generate API HTML and an actual test report corresponding to the packaged source.
- [x] Confirm all three packaged source notebooks have empty outputs.
- [x] Review the public file set: no source measurements, private runs, environments or executed copies.
- [x] Verify the actual raw course CSV reproduces the full-extract prepared data and recorded experiment results.
- [ ] Exclude ignored `config/local.json` together with `results/` and local data when preparing the repository clone.
- [ ] Maintain real version-control commits and a functional main branch.
- [ ] Provide the actual repository URL and verify assessor access.
- [ ] Submit the personal report and the final repository's zipped clone through Moodle.
- [ ] Check Moodle/Unit Overview for actual deadlines and presentation arrangements.

Do not ZIP a working directory containing ignored private results and call it a
repository clone. API generation does not require GitHub Pages hosting. The course
does not mandate a filename main.py or a specific permissive license.
